# Reports Sync API Documentation

## Overview

This document describes the complete flow for secure report syncing, from license activation to authenticated report uploads. The process is programming language independent and suitable for any client implementation.

---

## 1. License Activation

Before using the API, the client must activate a license.

### Endpoint
`POST /api/license/activate`

### Request Body
```
{
  "licenseKey": "string",
  "deviceId": "string"
}
```

### Success Response
```
{
  "success": true,
  "message": "License activated",
  "data": {
    "school": { ... },
    "config": {
      "licenseKey": "string",
      "licenseDays": 365,
      "registeredAt": "2025-08-04T12:34:56.789Z",
      "validUntil": "2026-08-04T12:34:56.789Z"
    },
    "securityParams": {
      "apiKey": "string",
      "deviceFingerprint": "string",
      "offlineToken": "string",
      "signingKey": "string"
    }
  }
}
```

- **Save** the `apiKey`, `offlineToken`, and `signingKey` for use in all future requests.
- The `signingKey` is used to generate request signatures.

---

## 2. Preparing Authenticated Requests

All report syncing requests must include the following headers:

| Header                | Required | Description                                                                                 |
|-----------------------|----------|---------------------------------------------------------------------------------------------|
| x-api-key             | Yes      | API key from license activation response                                                    |
| x-device-id           | Yes      | Unique device identifier (same as used in activation)                                       |
| x-request-timestamp   | Yes      | Epoch timestamp (ms) for request time (current time, generated by client)                   |
| x-request-signature   | Yes      | HMAC signature for request body (see below)                                                 |
| x-offline-token       | Yes      | Offline token from license activation response                                               |
| Content-Type          | Yes      | `application/json`                                                                          |

### Generating the x-request-signature

- The client must generate a signature for every request using the `signingKey` from activation.
- The signature algorithm must match the server's logic (typically HMAC-SHA256 or similar):

**Signature Input:**
- The request body (as a string, e.g., JSON.stringify in JS)
- The device ID
- The request timestamp

**Signature Generation (pseudo-code):**
```
signature = HMAC_SHA256(
  requestBody + deviceId + requestTimestamp,
  signingKey
)
```
- Set this value as the `x-request-signature` header.

## 3. Reports Syncing

### Endpoint
`POST /api/reports/bulk`

### Request Body
An **array** of report objects (max 500 per request):

```json
[
  {
    "chapterId": "string",
    "chapterName": "string",
    "subjectId": "string",
    "userId": "string",
    "userName": "string",
    "timestamp": "2025-08-04T12:34:56.789Z",
    "languageId": "string",
    "boardId": "string",
    "classId": "string",
    "sessionId": "string",
    "categoryId": "string",
    "subcategoryId": "string",
    "contentId": "string",
    "contentName": "string",
    "resourceType": "video | audio | questions | book | interactive | other",
    "metrics": {
      "duration": 12345,
      "videoProgressMs": 1000,
      "videoProgressPercentage": 50,
      "playCount": 1,
      "rewindCount": 0,
      "forwardCount": 0,
      "totalDuration": 3600000,
      "totalQuestions": 10,
      "correctAnswers": 8,
      "totalQuestionsAttempted": 9,
      "score": 80,
      "totalMarks": 100,
      "pagesViewed": 5,
      "totalPages": 10
    },
    "deviceInfo": {
      "id": "string",
      "type": "mobile | tablet | ifp | tv | other",
      "os": "android | ios | windows | linux | macos | other"
    },
    "metadata": {
      "schoolId": "string",
      "licenseKey": "string",
      "projectId": "string"
    }
  }
]
```

#### Required Fields
- All top-level fields except for some `metrics` subfields (which depend on `resourceType`) are required.
- `metrics.duration` is always required.

---

## 4. Example Flow

1. **Activate License:**
   - Call `/api/license/activate` with `licenseKey` and `deviceId`.
   - Save `apiKey`, `offlineToken`, and `signingKey` from the response.
2. **Prepare Reports:**
   - Collect report data as per schema above.
3. **Generate Signature:**
   - For each sync request, generate a new `x-request-timestamp` (current time in ms).
   - Generate `x-request-signature` using the request body, device ID, timestamp, and signing key.
4. **Send Reports:**
   - POST to `/api/reports/bulk` with all required headers and the reports array as the body.
5. **Handle Response:**
   - On success, store sync status and handle any invalid reports as needed.

## 5. Response

### Success (HTTP 200)
```json
{
  "message": "Reports stored successfully",
  "data": {
    "totalCount": 2,
    "validCount": 2,
    "invalidCount": 0,
    "syncStatus": [
      {
        "reportId": "licenseKey_d1g1_userId_d1g1_timestamp",
        "synced": true,
        "error": null,
        "storedAt": "2025-08-04T12:34:56.789Z"
      }
    ],
    "details": {
      "validReports": [
        {
          "id": "mongodb_object_id",
          "reportId": "licenseKey_d1g1_userId_d1g1_timestamp",
          "syncedAt": "2025-08-04T12:34:56.789Z"
        }
      ],
      "invalidReports": []
    }
  }
}
```

### Validation Error (HTTP 400)
```json
{
  "message": "Reports must be an array",
  "errorCode": "BAD_REQUEST"
}
```
or
```json
{
  "message": "Batch size cannot exceed 500 reports",
  "errorCode": "BAD_REQUEST"
}
```

### Authentication Error (HTTP 401)
```json
{
  "message": "Invalid API key",
  "errorCode": "UNAUTHORIZED"
}
```

### Server Error (HTTP 500)
```json
{
  "message": "Unexpected error",
  "error": "Error details"
}
```

---

## 6. Notes

- **Batch Limit:** Maximum 500 reports per request.
- **Idempotency:** Each report is uniquely identified by `reportId`.
- **Partial Success:** If some reports are invalid, valid ones are still stored and details are returned.
- **Timestamps:** Use ISO 8601 format for all date fields.
- **Security:** Never share your `signingKey` or `offlineToken` with unauthorized parties.

---

## 7. Example Request

```bash
curl -X POST https://yourdomain.com/api/reports/bulk \
  -H "x-api-key: YOUR_API_KEY" \
  -H "x-device-id: DEVICE_ID" \
  -H "x-request-timestamp: 1754304896789" \
  -H "x-request-signature: SIGNATURE" \
  -H "x-offline-token: TOKEN" \
  -H "Content-Type: application/json" \
  -d '[{ ...reportObject1 }, { ...reportObject2 }]'
```
